# Project documents - distinct jobs

- **[EOD_STATUS.md](../EOD_STATUS.md): summarize the DAY.** What happened that Pacific day, results, decisions, unresolved work and blockers. Preserve dated history and distinguish implementation, tests, merge, deployment and owner acceptance. Use [the EOD workflow](PROJECT_EOD_UPDATE.md).
- **[DAILY-SYNC.md](../DAILY-SYNC.md): get up to speed, sync the project and get ready to WORK.** Read the application, setup, development process, current work and latest owner decisions. Reconcile old/conflicting instructions before advising or acting. This is project orientation, not just a status report. Follow [the sync protocol](DAILY_SYNC_PROTOCOL.md).
- **Development Workflow: the CURRENT way this project is developed.** Use the existing authoritative workflow sources linked below; respect issue/branch/PR, review, DEV testing, owner acceptance and release gates specific to this project.
- **[Application Setup](APPLICATION_SETUP.md): the durable setup/operations facts.** Start with existing detailed setup, environment and runbook sources; preserve verified facts and correct their source when they change. Do not invent or duplicate setup instructions.
